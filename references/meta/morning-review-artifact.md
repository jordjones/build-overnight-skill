# Morning-review artifact

The human-facing handoff. What the user sees when they wake up. Source: R5.

## The 3-surface handoff

| Surface | Purpose | Location |
|---|---|---|
| **PR** | One-tap review and merge gate | GitHub, draft PR with `[OVERNIGHT]` prefix |
| **OVERNIGHT_RUN_REPORT.md** | Detailed structured report | `.overnight/<run-id>/FINAL_REPORT.md`, linked from PR body |
| **macOS local notification** | "Your run is done" ping | At completion only; silent during the run |

If `why_stopped != DONE`, replace `FINAL_REPORT.md` with `FAILURE.md` (same structure plus resume-command section).

## OVERNIGHT_RUN_REPORT.md template (committed inside `.overnight/<run-id>/`)

Larger version of the PR body — used as the source of truth for the audit trail. Same sections, plus:

- **PRD.md** verbatim (copied)
- **PLAN.md** with per-item status (DONE / WIP / BLOCKED / OUT-OF-SCOPE / DROPPED)
- **STATE.md** final snapshot
- **Full events.jsonl path** for telemetry
- **Git history** since the entry point:
  ```
  git log --oneline overnight/<run-id>/ckpt-h0..HEAD
  ```

## Trust signals — mandatory in every report

1. **Test run output pasted verbatim** (not summarized): "`pytest -q` exit 0: 47 passed in 4.2s"
2. **Lint pass evidence**: ruff/eslint/mypy exit codes + counts
3. **Build pass evidence**: if applicable, `npm run build` / `cargo build` exit codes
4. **Diff hash** matching the commit's actual diff (prevents fabrication)
5. **No-test-weakening attestation**: grep summary `grep -RE "skip|xfail|@unittest.skip" tests/ | wc -l` showing zero new instances
6. **No-mock-of-SUT attestation**: for refactor / bug-hunt categories
7. **Cache-hit summary**: overall + per-iteration top/bottom
8. **Drift score**: aggregate over the run

## Uncertainty signals — mandatory whenever applicable

1. **`[UNVERIFIED]` marker** on any code path the agent could not verify with a test
2. **`[LOW-CONFIDENCE]` marker** on inferred types, names, or behaviors
3. **`[ASSUMPTION]` block** at the top listing every assumption that filled an underspecified slot
4. **Auto-downgrade rule**: if ANY `[UNVERIFIED]` touches a path matching `core/|security/|data/|auth/|payment/`, the Recommendation field auto-downgrades to REVIEW (cannot be SHIP).
5. **Uncertainty count**: total `[UNVERIFIED]` + `[LOW-CONFIDENCE]` markers in the diff
6. **"Things I did not change"** section listing nearby code the agent intentionally avoided
7. **"Things I did but am unsure about"** section — explicit uncertainty surfacing

## Notification cadence

Per Phase 0.6 + R5 §6:
- **Run start:** one macOS local notification (`osascript -e 'display notification "..." with title "..."'`)
- **Middle hours:** silent. No SMS, no Slack, no email. Don't wake the user.
- **Hard-crash:** one macOS local notification immediately.
- **Completion:** one macOS local notification.

The notification text:
```
[OVERNIGHT] <category> done — $XX in YYh ZZm — PR #NN — Recommend: SHIP/REVIEW/REVERT
```

v1 ships local notifications only. Slack/SMS/email via ntfy.sh or similar is deferred to v1.1.

## "Should I ship?" decision support

The Recommendation field at the top of the PR body is computed:

```
recommendation = SHIP   if (
    why_stopped == DONE
    AND test_pass == True
    AND lint_pass == True
    AND no_test_weakening
    AND no_uncertain_critical_paths   # auto-downgrade rule
    AND drift_score_aggregate <= 2/5
    AND cost_within_ceiling
)
recommendation = REVERT if (
    why_stopped in {FORCE_KILL, RISK}
    OR test_pass == False
    OR secret_scan_failed
)
recommendation = REVIEW otherwise
```

The morning workflow becomes: read the Recommendation, skim the diff, click Merge or close-and-rerun. Don't trust SHIP blindly — the agent could be wrong about its own work — but trust the downgrade signals.
